2. ОБЩЕНИЕ С ВЛАДЕЛЬЦЕМ
======================================================================
- Владелец пишет по-русски, часто с опечатками, присылает скриншоты (телефон и компьютер).
  Отвечать по-русски, просто, без технического жаргона, коротко: что сделано, что проверено, что нужно от него.
- Задачи обычно пачкой по пунктам (1, 2, 3…) — делать все, отчитываться по каждому пункту.
- Если что-то не проверено на реальном сайте/устройстве — честно сказать и попросить проверить.
- Решения, которые меняют поведение для людей (права ролей, отключение функций, тестовый режим SMS),
  не делать молча — предложить и спросить.
- Владелец любит «как на Wildberries», но дизайн должен ОТЛИЧАТЬСЯ от WB (свои цвета).
- Всегда проверять мобильную версию (ширина 375–390 px): владелец часто присылает баги с телефона.

3. ЦИКЛ КАЖДОЙ ПРАВКИ (обязательно)
======================================================================
1) Правка кода.
2) Если менялся client/src — собрать фронтенд: cd client && npx vite build
   ВАЖНО: папка client/dist лежит в репозитории, CI падает, если dist устарел.
3) Перезапустить локальный сервер и проверить в браузере (Playwright, скриншоты), в т. ч. 375 px.
4) Тесты: mysql -e "DELETE FROM sklad.SmsCode"; cd server && npm test   (все должны пройти)
   Новая функция → добавить тест в server/test/api.test.js.
5) Поднять версию в package.json (2.9.3 → 2.9.4 исправление, 2.10.0 новая функция), README при необходимости.
6) Перед коммитом: git grep на секреты (токен WB начинается с "eyJhbGciOi"), никаких паролей/ключей.
7) Коммит от имени владельца, сообщение по-русски:
   git -c user.email=mahmadali91@gmail.com -c user.name=mahmadali91 commit
   В конце сообщения две строки:
     Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>
     Claude-Session: <ссылка на текущую сессию>
   Никаких названий/ID моделей в коде, комментариях, README.
8) git push -u origin main (при сетевой ошибке — до 4 повторов с паузой 2/4/8/16 с).
9) Дождаться проверок GitHub:
   gh api repos/mahmadali91/sklad/commits/$SHA/check-runs --jq '[.check_runs[]|.status+":"+(.conclusion//"")]|join(",")'
   (GraphQL из сессии недоступен — только REST: gh api …; gh run view/list работают)
10) Проверить сайт: curl -s https://botmi.ru/api/health → "app":"<версия>","version":"<SHA>","db":"ok".
11) Коротко отчитаться владельцу.

4. ЛОКАЛЬНОЕ ОКРУЖЕНИЕ (облачный контейнер)
======================================================================
- MariaDB часто останавливается: service mariadb start. Пароль admin локально: test-password.
- Сервер: cd server && node src/index.js (порт 3000). Перезапуск — только так:
    for p in $(pgrep -f "^node src/index.js"); do kill $p; done
  НЕ использовать pkill -f "node src/index.js" — убивает собственную оболочку (exit 144).
- Playwright: NODE_PATH=$(npm root -g) node script.cjs; Chromium в /opt/pw-browsers, "playwright install" не запускать.
  В этом Chromium НЕТ H.264 — видео MP4/HLS с WB тут не играет (это не баг сайта). Для теста — VP9 через ffmpeg.
- Запросы к внешним сайтам из node: NODE_USE_ENV_PROXY=1 NODE_EXTRA_CA_CERTS=/root/.ccr/ca-bundle.crt.
  Браузер Playwright через прокси не ходит на localhost — перехватывать внешние запросы через page.route.
- curl на botmi.ru без cookie получает заглушку Beget → добавлять: -b "beget=begetok".
- Миграции без интерактива:
    D=prisma/migrations/$(date +%Y%m%d%H%M%S)_name; mkdir -p $D
    npx prisma migrate diff --from-schema-datasource prisma/schema.prisma --to-schema-datamodel prisma/schema.prisma --script > $D/migration.sql
    npx prisma migrate deploy && npx prisma generate
  (prisma migrate dev в сессии не работает)
- rm -rf внутри bash -c с переменными блокируется проверкой безопасности — писать тест-скрипт в файл с явными путями.
- Временные файлы — только в scratchpad сессии, не в репозитории. Папка backups/ — в .git/info/exclude.
- Тесты: перед запуском чистить SmsCode (лимит SMS по IP). Тест ABC-долей допускает погрешность округления.

5. ДЕПЛОЙ (Beget)
======================================================================
- .github/workflows/deploy.yml: тесты (MySQL 8 в CI!) → сборка → проверка dist → деплой → проверка /api/health.
- Репозиторий закрытый, поэтому: Actions делает git archive и передаёт его по SSH
  (ssh … "$GITHUB_SHA" < app.tar.gz). Ключ BEGET_SSH_KEY ограничен: на сервере запускается только
  ~/.sklad-deploy.sh (создаётся deploy/setup-autodeploy.sh), он кладёт архив и запускает deploy/beget.sh с ARCHIVE=.
  В журнале Actions должно быть «Автодеплой версии … (архив …)» и «Готово».
- deploy/beget.sh: Node в ~/botmi.ru/.node, код ~/botmi.ru/app, фото ~/botmi.ru/uploads, настройки ~/botmi.ru/sklad.env.
- Статику (в т. ч. /admin/ index.html и /uploads) на Beget отдаёт nginx напрямую — заголовки Express до неё НЕ доходят.
  Защита админки от фреймов — скриптом в client/admin/index.html. .htaccess с новыми директивами не трогать
  (ошибка = 500 на весь сайт).
- Новый сайт/домен при закрытом репозитории — установка из ZIP (docs/DEPLOY.md, раздел 2). raw.githubusercontent.com не работает.
- Резервная копия: админка → Настройки → «Резервная копия» (база .sql.gz и фото .tar.gz); инструкция docs/DEPLOY.md.
  Дамп обязан работать и на MariaDB, и на MySQL 8 (SHOW CREATE TABLE отдаёт колонку под разными именами).

6. СТЕК И УСТРОЙСТВО КОДА
======================================================================
- server: Node/Express 4, Prisma 6 + MySQL/MariaDB. client: React 18 + Vite 6, Tailwind v4, lucide-react, Recharts.
  Витрина и админка — одна сборка, две точки входа (index.html → dist/shop.html, admin/index.html).
- Тёмная тема: переопределение переменных цветов под .dark в client/src/index.css.
  Светлая тема — :root:not(.dark) (серый фон страницы, белые .card/.panel с рамкой).
  Если добавляешь bg-white/NN — добавь и правило для .dark (иначе в тёмной теме будет белое пятно).
- Товары (как на WB): МОДЕЛЬ (ProductGroup) → КАРТОЧКА на каждый цвет (parentId = null, свои фото, артикул)
  → РАЗМЕРЫ (parentId = id карточки, свой штрихкод/остаток/цена, size + sizeRu).
  У размеров нет своих фото → везде использовать util.fillImages() (фото карточки того же цвета).
  Первое медиа может быть видео → в превью брать только images where kind='image'.
- Артикул числовой: 10000000 + id карточки (util.articleOf / idOfArticle).
- Склад: партии Batch/BatchUse, FIFO-себестоимость, всё через util.changeStock(...).
- Каталог по умолчанию: сначала закреплённые (featuredPos 1–20), потом новые.
- Витрина: server/src/routes/shop.js; SEO-рендер server/src/seo.js; задачи по расписанию jobs.js;
  разовые миграции данных upgrade.js; WB — wb.js и routes/wb.js.
- PDF (ценники 58×40, лист подбора): client/src/pdf.js, jsPDF + шрифт DejaVu (client/public/fonts, только кириллица/₽).
  Длинный текст подгонять по ширине колонки (fitSize), не допускать наездов.
- Видео: общий плеер client/src/components/VideoPlayer.jsx (HLS через hls.js, Safari — нативно).
  WB-видео — только поток 1440p .m3u8 (H.264). .mov сохраняется как .mp4. Service worker не кэширует медиа.
- Капча: своя, «доказательство работы» (server/src/captcha.js, client/src/captcha.js) —
  на запрос SMS-кода всегда, на вход в админку после 3 ошибок. IP клиента — только util.clientIp().
- База знаний: client/src/kb/articles.js + картинки client/public/kb.
  При изменении интерфейса обновлять статьи и пересоздавать скриншоты/видео на демо-копии (НЕ на рабочей базе):
  отдельная база sklad_kb, сервер на порту 3200 с UPLOAD_DIR в scratchpad, демо через POST /api/admin/demo,
  затем node scripts/kb-shots.cjs и scripts/kb-videos.cjs (нужны Playwright, Pillow, ffmpeg).
  Кнопка «Справка» в шапке: соответствие страниц статьям — ROUTE_HELP в articles.js.

9. ЧАСТЫЕ ГРАБЛИ (уже ловили)
======================================================================
- Мобильная вёрстка: широкие таблицы → overflow-x-auto или список карточек на телефоне; модалки p-2 на телефоне.
- Блок с aspect-ratio во flex/grid растягивается по картинке → ставить img absolute inset-0, сетку content-start.
- Отметки на скриншотах: сначала прокрутить, потом мерить все элементы (иначе рамки съезжают).
- Счётчики (избранное, корзина) должны совпадать со списком: убирать скрытые/удалённые товары.
- Перед выкладкой проверять и светлую, и тёмную тему.
